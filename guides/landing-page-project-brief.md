# Briefing a small static landing page: what a client should provide

*Original GIA educational guide · November 2026 · not a paid client case.*

If you need a portfolio page, event information page or simple business landing page, a precise one-page brief often saves more time than adding dozens of design examples.

## Start with the outcome

Write one sentence explaining what visitors should do: understand your offer, send an inquiry, view a portfolio or register interest. A static page can explain information and link to an existing service, but payment processing, user logins and databases require additional architecture and scope.

## The essential brief

| Question | Example answer |
|---|---|
| Who will visit? | Local clients looking for a service |
| What is the primary action? | Open an existing contact form |
| What sections are needed? | Headline, benefits, sample work, FAQ, contact |
| What material is already available? | Authorized logo, original copy and brand colors |
| Which languages? | English, Ukrainian or Polish |
| Which devices matter? | Mobile first, then desktop |
| What is the budget and deadline? | Agreed before implementation |
| Who owns images, fonts and text? | Client supplies rights or approves replacements |
| Where will the page be hosted? | Existing hosting, agreed separately |

## The accessibility baseline

A reasonable starting point is semantic HTML, visible keyboard focus, sufficient contrast, descriptive link text and responsive layout. Before shipping, verify on real mobile and desktop browsers and test the contact flow. A working link to an *existing* form is not the same as building a secure backend.

## A useful project request

> I need a two-language static landing page for a small service business. I have a logo and approved text. Please quote a mobile-responsive layout with four sections, accessibility basics and deployment instructions. My budget is [amount], and I need delivery by [date]. Please confirm how AI assistance, asset rights and revisions are handled.

Don't send passwords or live access credentials publicly. Provide an approved private channel only after agreement.
